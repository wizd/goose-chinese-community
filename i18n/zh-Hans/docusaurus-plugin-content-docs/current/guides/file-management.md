作为自主代理，goose 会按你给出的指令完成任务。这通常涉及本地文件：既要找到该用的文件，也要安全地修改它们。

本指南说明如何在 goose 中高效访问和引用文件，并给出安全文件操作的基本实践，例如监控变更、必要时回退，以保持代码库完整。

## 文件访问

### 在 goose 桌面版中快速搜索文件

goose 桌面版带有模糊文件搜索，你可以在聊天界面里直接引用文件，不必手动打开系统文件对话框。这样能快速找到文件，并把它加进发给 goose 的消息。

1. 在聊天输入框中输入 `@`，打开文件搜索框
2. 继续输入，用不区分大小写的模糊匹配筛选文件（例如 `@readme`、`@config.js`、`@src/main`）

   浏览结果：
   - 用方向键（↑/↓）在搜索结果中移动
   - 点击或按 `Enter`，把选中的文件路径插入消息
   
3. 准备好后，把消息发给 goose 即可

:::info
不选文件就关闭搜索框：按 `Esc`，或点击聊天输入框。
:::

**智能特性：**
- **模糊匹配**：能匹配不完整文本，并优先命中词边界
- **高亮结果**：在搜索结果中高亮匹配到的字符
- **性能优化**：最多扫描 5 层目录，并做智能过滤
- **自动过滤**：自动排除常见目录，如 `.git`、`node_modules`、`__pycache__`、`target`、`dist` 和 `build`
- **隐藏文件夹支持**：包含重要配置目录，如 `.github`、`.vscode`、`.idea`、`.config`，以及其他 CI/CD 目录（`.circleci`、`.gitlab`、`.azure`、`.jenkins`）
- **跨平台**：从用户目录开始搜索（macOS 为 `/Users`，Windows 为 `C:\Users`，Linux 为 `/home`）
- **视觉区分**：用清晰图标区分文件和目录

## 文件管理最佳实践

### 版本控制

始终用 Git 等版本控制系统跟踪代码库变更。这样可以避免意外覆盖，也方便回到之前的状态。在对代码库运行 goose 之前先提交变更。用分支把实验性改动和主代码库分开。

### 验证与测试

在 goose 修改文件之前和之后都安排验证与测试。运行单元测试，确认 goose 所做的改动。用预发环境检查这些改动能否与整个系统良好集成。

### 变更审查

人工审查，或用自动化代码审查来保证生成代码和改动的质量。用 diff 等工具直观查看 goose 的修改。通过团队成员或 CI/CD 流水线建立审查流程。

### 代码库组织

把代码库拆成边界清晰的模块或子目录，便于管理。用模块化方式隔离 goose 需要访问的代码。你也可以指定希望 goose 处理的具体目录或文件路径。
